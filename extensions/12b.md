
## 12.9 Reinforcement Learning with Verifiable Rewards: GRPO and Reasoning Training

### Conceptual Deep Dive
For tasks with checkable answers (maths, code, formal constraints, structured extraction), you can train with **RL from verifiable rewards (RLVR)** instead of a learned reward model. **GRPO** (group relative policy optimisation) samples G completions per prompt, scores each with a programmatic reward, and uses the group-normalised reward `(r - mean) / std` as the advantage, removing the value network that PPO needs. A KL penalty to a reference model keeps the policy close to its starting point. Reward design is the craft: **correctness** reward, **format** reward (reasoning inside tags, answer in a box), length or efficiency penalties, and safeguards against reward hacking (model learns to exploit the verifier). Typical recipe: SFT warm-start on reasoning traces, then RLVR on a curriculum from easy to hard. Edge cases: all samples in a group correct or all wrong (zero advantage, wasted compute), verifiers with false positives, reward hacking via formatting tricks, and response length growth.

### Cross-Connection Scenarios
Preference optimisation (12.4), reasoning models (5.5, 2.7), sandboxed code execution (10.9), evaluation (10).

### Production Anti-Patterns
- Rewarding only the final format, not correctness.
- Weak unit tests that can be passed by hard-coding outputs.
- No held-out set to detect reward hacking.

### Minimal Working Code
```python
import re
import statistics

def reward(completion: str, gold: str) -> float:
    fmt = 0.1 if re.search(r"<think>.*?</think>\s*<answer>.*?</answer>", completion, re.S) else 0.0
    m = re.search(r"<answer>(.*?)</answer>", completion, re.S)
    correct = 1.0 if m and m.group(1).strip() == gold.strip() else 0.0
    return fmt + correct

def group_advantages(rewards: list[float], eps: float = 1e-6) -> list[float]:
    mu, sd = statistics.mean(rewards), statistics.pstdev(rewards)
    return [(r - mu) / (sd + eps) for r in rewards]

group = ["<think>2+2</think><answer>4</answer>", "<answer>5</answer>", "<think>x</think><answer>4</answer>", "4"]
rs = [reward(c, "4") for c in group]
print(rs, [round(a, 2) for a in group_advantages(rs)])
```

## 12.10 Synthetic Data Generation Pipelines

### Conceptual Deep Dive
Synthetic data amplifies a small seed set. Pipeline: **seed** (real examples, taxonomies, documents) to **generate** (a strong teacher model produces instructions and responses; techniques: Self-Instruct, Evol-Instruct, persona-driven prompts, document-grounded QA, rejection sampling) to **filter** (rule checks, schema validation, execution/verification, judge scoring, dedupe with MinHash or embeddings, diversity sampling by clustering) to **review** (human audit of a stratified sample) to **train**. Quality levers: ground generation in real documents to avoid fabricated facts, vary personas/styles/difficulty, include hard negatives and refusals, and verify with tools where possible (run the code, check the maths). Risks: **model collapse** from training repeatedly on model output, inheriting teacher errors and biases, licence restrictions on using a vendor's outputs to train competing models, and benchmark contamination. Keep provenance metadata (teacher, prompt version, filters) for every row.

### Cross-Connection Scenarios
Dataset curation (12.2), judge filters (10.3), eval contamination (10.8), distillation (12.6), licensing (14.7).

### Production Anti-Patterns
- Training on unfiltered teacher output.
- Using the same model family to generate and judge.
- No provenance, so a bad batch cannot be traced and removed.

### Minimal Working Code
```python
import hashlib
import random

def dedupe_near(rows: list[dict], key="prompt", shingle: int = 3, threshold: float = 0.8):
    def shingles(t):
        w = t.lower().split()
        return {" ".join(w[i:i + shingle]) for i in range(max(1, len(w) - shingle + 1))}
    kept, sigs = [], []
    for r in rows:
        s = shingles(r[key])
        if all(len(s & t) / max(len(s | t), 1) < threshold for t in sigs):
            kept.append(r)
            sigs.append(s)
    return kept

def stratified_audit_sample(rows: list[dict], by: str, per_group: int = 5, seed: int = 0):
    rng, groups = random.Random(seed), {}
    for r in rows:
        groups.setdefault(r[by], []).append(r)
    return [x for g in groups.values() for x in rng.sample(g, min(per_group, len(g)))]

rows = [{"prompt": "How do I reset my password today", "cat": "acct"},
        {"prompt": "How do I reset my password today please", "cat": "acct"},
        {"prompt": "Cancel my subscription", "cat": "billing"}]
print(len(dedupe_near(rows, threshold=0.5)))
```

## 12.11 Multi-LoRA Serving and Adapter Lifecycle Management

### Conceptual Deep Dive
Serving one base model with many small adapters (per customer, language or task) is far cheaper than one full model each. Engines (vLLM, LoRAX, TGI) keep the base weights resident, load adapters on demand into an LRU cache, and batch requests for **different adapters together** (e.g. punica/S-LoRA kernels). Lifecycle: train adapter, evaluate, register with metadata (base revision hash, rank, target modules, dataset version, eval scores), promote through stages, and hot-load without restarting the server. Operational concerns: adapter cache size and eviction latency, per-tenant isolation, base-model upgrades invalidating all adapters (retrain or re-validate), merging adapters for peak-throughput hot paths, and routing requests to the correct adapter safely. Edge cases: adapter trained against a different base revision loading silently but behaving badly, rank/alpha mismatch, and adapter sprawl.

### Cross-Connection Scenarios
LoRA training (12.3), serving engines (13.1), registry and promotion (15.4, 15.9), multi-tenancy (4.7).

### Production Anti-Patterns
- Loading an adapter without verifying the base-model hash.
- Unbounded adapter count with no eviction policy.
- Letting a client choose any adapter name (cross-tenant access).

### Minimal Working Code
```python
from collections import OrderedDict

class AdapterCache:
    def __init__(self, capacity: int, loader):
        self.cap, self.loader, self.store = capacity, loader, OrderedDict()

    def get(self, name: str):
        if name in self.store:
            self.store.move_to_end(name)
            return self.store[name], "hit"
        adapter = self.loader(name)
        self.store[name] = adapter
        if len(self.store) > self.cap:
            self.store.popitem(last=False)         # evict least recently used
        return adapter, "miss"

cache = AdapterCache(2, lambda n: f"weights:{n}")
print([cache.get(n)[1] for n in ["a", "b", "a", "c", "b"]])
```

```python
def resolve_adapter(tenant: str, requested: str | None, registry: dict, base_hash: str) -> str:
    entry = registry.get((tenant, requested or "default"))
    if entry is None:
        raise PermissionError("adapter not available for tenant")
    if entry["base_hash"] != base_hash:
        raise RuntimeError("adapter was trained on a different base revision")
    return entry["path"]

reg = {("acme", "default"): {"path": "adapters/acme-v3", "base_hash": "abc123"}}
print(resolve_adapter("acme", None, reg, "abc123"))
```
