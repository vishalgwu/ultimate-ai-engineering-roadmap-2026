
## 9.9 GraphRAG: Building and Querying a Knowledge Graph

### Conceptual Deep Dive
Vector search retrieves similar passages but struggles with questions that span many documents ("what are the main themes?") or multi-hop reasoning ("which suppliers of X are also in region Y?"). **GraphRAG** builds a graph at ingestion: an LLM extracts **entities and relations** from each chunk; nodes are deduplicated (entity resolution); a community-detection algorithm (Leiden) clusters the graph hierarchically; the LLM writes a **summary per community**. Query modes: **local** (find entities near the query, expand neighbours, retrieve their source chunks) and **global** (map-reduce over community summaries). Costs: many LLM calls at indexing, re-indexing on updates, and extraction errors. Lighter variants: entity-linked chunk graphs, LightRAG, and graph databases (Neo4j) queried with Cypher generated by the LLM. Use when questions are relational or corpus-wide and plain hybrid retrieval has been measured to fail. Edge cases: entity aliasing ("IBM" vs "International Business Machines"), contradictory relations from different sources, and graph growth.

### Cross-Connection Scenarios
Advanced retrieval (9.3), text-to-query (9.6), cost of indexing (2.4), evaluation of multi-hop questions (10.8).

### Production Anti-Patterns
- Building a graph before establishing that hybrid retrieval is insufficient.
- No entity resolution, producing duplicate nodes.
- Letting the LLM write unconstrained Cypher against a production database.

### Minimal Working Code
```python
from collections import defaultdict, deque

class KG:
    def __init__(self):
        self.adj = defaultdict(set)
        self.evidence = defaultdict(list)    # (a, rel, b) -> chunk ids

    def add(self, a: str, rel: str, b: str, chunk_id: str):
        a, b = a.lower(), b.lower()
        self.adj[a].add((rel, b))
        self.adj[b].add((f"~{rel}", a))
        self.evidence[(a, rel, b)].append(chunk_id)

    def neighbourhood(self, seeds: list[str], hops: int = 2):
        seen, q, edges = set(seeds), deque((s, 0) for s in seeds), []
        while q:
            node, d = q.popleft()
            if d == hops:
                continue
            for rel, nxt in self.adj[node]:
                edges.append((node, rel, nxt))
                if nxt not in seen:
                    seen.add(nxt)
                    q.append((nxt, d + 1))
        return edges

g = KG()
g.add("Acme", "supplies", "Globex", "c1")
g.add("Globex", "located_in", "Germany", "c2")
print(g.neighbourhood(["acme"], hops=2))
```

```python
EXTRACT_PROMPT = """Extract entities and relations from the text as JSON:
{"entities":[{"name":str,"type":str}],"relations":[{"source":str,"relation":str,"target":str}]}
Use canonical names. Only include facts stated in the text.

Text:
<<TEXT>>"""

def resolve_entities(names: list[str], same) -> dict[str, str]:
    """Greedy entity resolution: map each name to a canonical representative."""
    canon: dict[str, str] = {}
    reps: list[str] = []
    for n in names:
        match = next((r for r in reps if same(n, r)), None)
        if match is None:
            reps.append(n)
            match = n
        canon[n] = match
    return canon

norm = lambda s: "".join(c for c in s.lower() if c.isalnum())
print(resolve_entities(["Acme Corp.", "acme corp", "Globex"], lambda a, b: norm(a) == norm(b)))
```

## 9.10 Contextual Retrieval, RAPTOR and Hierarchical Indexing

### Conceptual Deep Dive
Chunks lose context when cut from their documents ("The company's revenue grew 3%" - which company, which quarter?). **Contextual retrieval** prepends a short LLM-generated situating sentence to each chunk before embedding and BM25 indexing (using prompt caching on the full document makes this affordable), typically cutting retrieval failures substantially when combined with hybrid search and reranking. **RAPTOR** recursively clusters chunks, summarises each cluster, and indexes summaries at multiple levels, so broad questions hit summaries while detailed ones hit leaves. **Hierarchical / parent-child indexes** store small child chunks for matching and return the larger parent. **Multi-vector per document** (summary, hypothetical questions, raw text) widens recall. Edge cases: stale summaries after document edits, summaries introducing hallucinated facts, and index bloat.

### Cross-Connection Scenarios
Chunking (9.2), prompt caching (2.4), reranking (9.4), freshness (9.6).

### Production Anti-Patterns
- Re-generating context for every chunk without document-level prompt caching.
- Using summaries as the only retrievable text for compliance questions.
- No refresh strategy for derived summaries.

### Minimal Working Code
```python
CONTEXT_PROMPT = """<document>
{doc}
</document>
Here is a chunk from the document:
<chunk>
{chunk}
</chunk>
Write one short sentence situating this chunk within the document to improve search retrieval.
Answer with the sentence only."""

def contextualize(llm, doc: str, chunks: list[str]) -> list[str]:
    out = []
    for c in chunks:
        ctx = llm(CONTEXT_PROMPT.format(doc=doc, chunk=c)).strip()
        out.append(f"{ctx}\n{c}")
    return out

fake = lambda p: "From Acme's Q2 2025 earnings report."
print(contextualize(fake, "doc text", ["Revenue grew 3% over the previous quarter."])[0])
```

```python
import numpy as np

def raptor_levels(chunks: list[str], embed, summarize, cluster_size: int = 4, max_levels: int = 3):
    """Return all nodes (leaves + summaries) with their level; clustering by simple sequential grouping."""
    nodes = [{"text": c, "level": 0} for c in chunks]
    current = chunks
    for level in range(1, max_levels + 1):
        if len(current) <= 1:
            break
        groups = [current[i:i + cluster_size] for i in range(0, len(current), cluster_size)]
        current = [summarize("\n".join(g)) for g in groups]
        nodes += [{"text": s, "level": level} for s in current]
    return nodes

print(len(raptor_levels([f"chunk {i}" for i in range(10)], None, lambda t: t[:20])))
```

## 9.11 Agentic RAG, Corrective RAG and Self-Reflection

### Conceptual Deep Dive
Fixed pipelines retrieve once. **Agentic RAG** lets the model plan retrieval: decide whether to retrieve, choose among sources (vector store, SQL, web, tools), issue several queries, inspect results, and iterate. **Corrective RAG (CRAG)** grades retrieved documents (correct / ambiguous / incorrect) and, if poor, rewrites the query or falls back to web search. **Self-RAG** trains/prompts the model to emit reflection signals (is retrieval needed? is the passage relevant? is the answer supported?). Implement as a bounded graph: retrieve, grade, (rewrite, retry up to N), generate, verify. Keep latency in check with a cheap grader, a hard cap on loops, and parallel retrieval. Edge cases: graders that over-reject, infinite rewrite loops, and conflicting evidence across sources.

### Cross-Connection Scenarios
Agents (11), graph orchestration (11.3), query rewriting (9.3), verification (9.5), evaluation of trajectories (11.6).

### Production Anti-Patterns
- Unbounded retrieve-grade-rewrite cycles.
- Using the large model as grader for every chunk.
- No fallback answer when all attempts fail.

### Minimal Working Code
```python
def corrective_rag(question, retrieve, grade, rewrite, generate, max_rounds: int = 2, min_good: int = 2):
    query, trail = question, []
    for round_ in range(max_rounds + 1):
        docs = retrieve(query)
        good = [d for d in docs if grade(question, d) == "relevant"]
        trail.append({"query": query, "retrieved": len(docs), "good": len(good)})
        if len(good) >= min_good:
            return {"answer": generate(question, good), "trail": trail}
        query = rewrite(question, query, docs)
    return {"answer": "I couldn't find enough reliable information to answer that.", "trail": trail}

out = corrective_rag("refund window?", lambda q: ["30 days", "shipping info"],
                     lambda q, d: "relevant" if "days" in d else "irrelevant",
                     lambda q, old, docs: old + " policy", lambda q, d: f"Answer from {d}", min_good=1)
print(out)
```

```python
def route_sources(question: str, sources: dict[str, str], llm) -> list[str]:
    """Let a cheap model choose which sources to query; validate the answer against known names."""
    catalog = "\n".join(f"- {name}: {desc}" for name, desc in sources.items())
    reply = llm(f"Sources:\n{catalog}\nQuestion: {question}\nList the source names to query, comma separated.")
    chosen = [s.strip() for s in reply.split(",")]
    return [s for s in chosen if s in sources] or list(sources)[:1]

print(route_sources("revenue last quarter", {"sql": "finance tables", "wiki": "company handbook"},
                    lambda p: "sql, unknown"))
```
